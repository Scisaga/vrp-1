# 场景规划与执行工作台

工作台以执行单元甘特排程为主，地图、工单和详情随同一选中对象联动。全局入口为场景、路网包管理、任务中心和服务设置；场景内区分数据与规则、规划方案、执行调度、历史记录。界面不得把求解完成当作方案生效，把计划播放当作实际执行，或把线程和内部修订号作为主要业务信息。

地图默认使用低饱和、低对比度的清淡底图，选中道路路线以深青色和白色描边突出。左上角可切换“清淡／标准”，偏好保存在当前浏览器；切换不改变道路数据或方案。自有矢量底图保持原样式。

操作成功和规划完成通过右上角通知提示，数秒后自动隐藏，也可手动关闭。完成通知只在观察到任务完成时显示一次，轮询、切换页面及重新打开历史方案不重复提示；任务进度、失败和需要处理的警告继续在相应工作区展示。

评分级别统一显示 Hard / Medium / Soft。趋势图使用同一个绘图区和求解耗时（秒）横轴，多级别曲线叠加、各自使用独立纵轴；颜色与图例、轴标题一致，线型也区分级别。默认“自动”：当前最佳 Hard 非零时只画 Hard；Hard 为 0 后，在同一张图中画该阶段的 Medium 和 Soft。未收到分数时显示等待，不把未知分数当作 Hard 为 0。可以手动查看全部级别或单独某一级别的完整历史；全部级别同样合并在一张图中，低优先级分数的真实下降仍保留。窄屏刻度可用科学记数法，接近的大整数使用明确标出基准值的 Δ 刻度，图例和采样点提示保留完整整数。任务进度由服务端约每秒采样并持久保存，保留首次有效进度和终态分数；最多 2048 点，长任务保留首尾并抽稀。刷新、切换场景和服务重启后恢复记录。旧任务或容量受限造成历史缺失时明确提示，不从终值伪造曲线。大整数先做整数差分再映射坐标。Hard 为 0 不表示工单全部分配；摘要说明未分配工单的实际计分级别和罚分。

曲线默认使用“自动细节”：当早期极值挤压后续变化时，保留带真实时间范围的全程概览，同时放大后续优化细节；细节图使用独立的线性纵轴并明确标注起止时间。可切换“完整过程”恢复全部采样的线性视图。摘要显示采样数、采样中可见的改善次数和起止分数；不改写、平滑或补造采样。长曲线的重复等分点减少标记，实际变化点与首尾保留。

20 个及以上执行单元默认紧凑排程，可切回标准行高；标题栏保留总数。紧凑排程使用可随屏幕增高的工作区，规划行高 24px，执行和对比为实际记录保留额外空间。“全部路线”进入全局地图，不再以首个执行单元代替总览；点击具体执行单元或工单后恢复详情与路线定位。

方案工作区使用平级的“排程 / 未分配工单（数量）/ 约束解释与风险”页签，不再套“检查与说明”折叠层。点击未分配数量切换到对应页签，选择工单回到排程并联动详情；页签切换保留筛选、缩放和选中对象。版本选择共用。规划及执行工作区的执行单元下拉框、工单搜索框直接放在甘特图区标题栏，替代“执行单元排程／数量”文字，与右侧缩放、全天和侧栏操作同排；窄屏换行，其他结果页不显示这两个筛选控件。任务信息通过顶部入口打开，包含线程、候选评估、冻结输入、结果下载与道路路径导入。

规划结果顶部将任务选择、已安排／未分配／行驶时间／行驶距离和采用按钮合并为一条工具栏，需要对比时在同排提供基准选择；窄屏按内容换行。删除“候选方案 · 采用后生效”说明行，已采用状态保留在任务选项中。业务版本过期时，在工具栏下方常驻显示内缩的浅橙提示卡，突出“业务数据已更新”并说明方案与当前业务版本；两侧及下方页签前均留 12px 间距，窄屏文案换行。重新规划入口保留在工具栏中。未分配的实际计分级别和罚分放在数量按钮的提示文字中，点击数量仍进入未分配工单页。

历史方案选择框旁提供“删除”，确认窗口说明清理范围。删除后切换到剩余方案；最后一条删除后返回规划空态，刷新不会恢复已删记录。运行中、已采用、执行审计或仍被引用的方案保留并显示原因。场景数据、共享矩阵和路网来源单独保留。

结果内容页签与“数据与规则”子页签共用紧凑样式：灰底边框标签、白底选中项和青色顶线，统一高度、内边距、悬停及键盘焦点状态。未分配数量使用同一小字计数样式；窄屏按共同规则缩小并换行。

全局导航、场景工作区、结果和数据页签均采用“线性图标＋文字”。图标共用内嵌 SVG 定义，随文字继承普通、悬停与选中颜色，不依赖图标字体或外部服务；图形不参与无障碍名称和键盘焦点，文字及数量保留。窄屏缩小间距和图标，极窄屏只显示品牌图形，为带文字的菜单留出空间。

排程与选中执行单元的地图详情同时呈现。宽屏并排；窄屏上下排列，并在地图详情区显示该执行单元的时间排程，地图和访问顺序相邻；手机继续纵向排列。允许收起整个详情区，不使用排程与地图切换页签。应用中人员、车辆等统一称“执行单元”；内部 Agent、resource_id 和稳定编号保持契约含义，历史演示名称“资源001”仅在展示时映射为“执行单元001”。

品牌使用已选定的 V＋1 单体标识：深青色与亮青色两块圆角形状组成 V，中间留白形成数字 1。导航标识和浏览器 favicon 共用透明背景 SVG，并通过资源版本号更新缓存；小尺寸保持完整轮廓和清楚的留白。

场景列表顶部并列放置“新建场景”和“导入场景”图标按钮，图形在按钮内水平、垂直居中，保留提示文字与无障碍名称。窄屏时两按钮位于搜索框右侧；列表底部不再放操作入口。工作台不提供创建演示场景的功能，验收使用独立的合成测试数据。

## 操作语义

- 静态场景提供“生成矩阵并规划”，串联路网准备、矩阵固化、新版本、求解和路径生成。普通求解按钮要求当前输入矩阵完整；服务端同样校验，不能只靠界面限制。保存场景后的自动预取只准备公共路网，不自动发起求解。
- 任务中心统一显示求解、路网包、矩阵和路径任务，进度按阶段及实际工作量展示。父任务可以展开子任务、依赖、错误和产物；部分失败可单独重试，路径失败不丢弃已完成方案。场景切换和刷新不能把旧准备结果写进新场景。
- 路网包管理显示源包覆盖、数据时间、版本、大小及引用，支持目录下载和服务器可见 PBF 导入。下载包与本地构图范围分别展示；更新只影响后续准备，清理必须通过引用检查。

- 规划求解/重新规划使用明确保存的场景版本。修改业务数据或规则会产生新版本，已存在任务的输入不变。
- 继续优化从指定终态任务的最终方案热启动，保持问题快照不变，只允许替换搜索参数。服务端检查场景仍为该版本；执行任务还必须匹配当前事实和生效计划基准，过期时明确拒绝并提示实时重排。原任务及结果保留。
- 实时重排从当前事实构造剩余问题。持续重排表示执行事件驱动的自动触发开关，与人工确认/自动采用分开配置；不会反复无条件启动求解。
- 采用静态方案并进入执行在同一操作中完成。按执行起点重新评价，必要装货访问纳入计划，但不会伪造实际装货、出发或完工事实。校验失败不创建半完成运营记录。
- 人工改派/改序以已有结果为基础生成独立候选，经服务端全量评分和结构检查后展示；不直接改写生效计划或实际执行状态。执行候选仍须满足版本和采用校验。
- 规划方案管理候选排程；“采用并进入执行”后，执行调度使用生效计划，记录实际出发、到达、服务、完工和装卸。执行后的重排仍先生成候选，采用后才更新生效计划。两个工作区的空状态说明这一先后关系。
- 场景“⋯”菜单和场景管理表提供删除入口。确认窗口说明全部历史版本、关联任务及折线的删除范围和未保存草稿；删除使用最新业务版本校验。活跃求解任务应先停止，已有执行历史的场景保留审计而不可删除。删除成功后移除本地草稿/缓存并切换到仍存在的场景，其他场景草稿继续保留。

## 界面关系

场景切换保留各自未保存的数据草稿、选中对象、工作区、结果选择和时间缩放；异步请求不得把前一个场景的数据写入后一个场景。轮询不得覆盖草稿。草稿保留在当前页面会话，可显式保存、导出或还原；重新加载/关闭页面会提示未保存内容。求解弹窗明确展示目标场景、业务动作和实际停机条件。

后台每 2.5 秒读取状态，业务版本、执行修订和任务数据未变化时不重建工作区，仅更新服务状态和时钟文字；实时执行视图继续推进时间显示。规划页面把所选任务写入地址中的任务编号段，刷新后继续查看同一任务；没有明确选择时优先查看运行或排队中的任务，再选择已有结果。异步响应返回时再次检查当前工作区和编辑状态，避免打断输入。规划与执行页面中，筛选或评分下拉框保持焦点时仍读取进度，仅更新进度标题、计时和图形区域，保留正在操作的控件；求解完成后挂载结果区。同一工作区确需重绘（状态变化、手动刷新、窗口尺寸变化）时，在矩阵等内容完成挂载后恢复页面和矩阵滚动位置，左侧场景列表也保留滚动位置。

弹窗和类似编辑面板统一采用紧凑桌面窗口样式：6px 窗口圆角、细边框、浅灰标题栏，关闭按钮贴右上角。桌面标题栏高 32px，标题和场景上下文同排，窄屏保留两行；正文独立滚动，标题栏和约 40px 高的底部操作栏始终可见。底部按钮高 26px、间距 6px，使用小圆角纯色和稳定的悬停/按下状态。草稿编辑统一使用“取消 / 应用”，操作栏明确标注应用到草稿；求解、采用、执行记录等操作保留具体动词。

数据与规则按工单、执行单元、地点、在途矩阵、约束与费用、原始输入的顺序使用紧凑页签，与下方内容面板相连。当前页签为白底和青色顶线，数量以小字显示；窄屏自动换行，不出现横向滚动条。支持左右方向键、Home / End 切换，页签切换保留场景草稿。

桌面场景标题、规划/执行状态、四个主工作区页签及常用动作合并为约 40px 的工作栏，长标题省略并保留完整提示；执行时钟同排显示。窄屏按标题、导航和操作分行，不挤压或隐藏导航。刷新、导出、场景设置、持续重排设置和还原草稿通过“⋯”菜单访问，支持外部点击关闭和 Esc 返回触发按钮，编辑单元格后直接打开菜单不会被重绘关闭。

不再设置独立数据摘要卡片。业务日期和设置入口位于数据页签右侧；点击日期进入紧凑编辑窗口，应用只修改草稿，保留原时间与时区，保存后才形成新版本。设置集中维护名称、时区及容量定义；已开始执行的日期和时区只读。原始输入中的待处理编辑先校验并合入草稿，不能被日期或设置修改覆盖。保存状态靠近保存按钮，普通未保存修改用橙色标记，版本冲突仍显示明确提示。工单/执行单元数量保留在子页签，矩阵质量保留在矩阵页。

工作表工具栏约 36px，直接保留搜索、撤销/重做、向下填充和新增；操作说明集中到“?”帮助窗口。桌面长表使用顶部压缩后释放的高度，表头继续固定在表格滚动区。标题高度不随滚动展开/收起，继续保持轮询和手动刷新时的滚动位置。

工单依赖直接在工单工作表的“前置工单”列维护，不设置独立关系页签。单元格支持编号/唯一名称输入、逗号分隔的多值、Excel 粘贴和搜索多选；多值为 AND，必须全部完成后才开始，允许跨执行单元执行。长列表省略并显示额外数量，选择器可查看完整列表；下游引用由前置列表反查，不另行维护。整批校验自引用、无效编号和循环依赖后才写入草稿，撤销恢复整批关系。新增依赖时若时序评分原先关闭，明确启用 1 hard；规划自动等待前置的预计完成，执行开始则必须已有全部前置的实际完成事实。服务中和已完成工单的前置关系不可改写。独立的历史同执行单元要求仍由原生关联和独立权重承载，不由这一列推导。

甘特图区分行驶、等待、服务、回程、实际完成/服务和候选变化；执行单元列固定，支持执行单元/工单筛选、时间缩放及未派工单定位。当前执行和候选对比共用时间范围，历史回看只读。地图采用 MapLibre，默认离线底图优先，缺包时以在线 OSM 底图过渡，支持自有瓦片/样式与 PMTiles；地图对象与甘特、详情共用选择状态。普通刷新保留地图实例和视角，各场景分别保存视角，定位操作才调整范围。无 WebGL 时使用坐标示意图；底图失败仍保留业务图层。

每个任务单独保存道路折线，按车辆、路段序号和冻结输入的起终点校验。存在匹配折线时显示道路路径，其余画访问顺序虚线，候选、当前计划和历史方案不能共用不匹配的折线。地图展示当前车辆位置、起终点和选中路线的访问序号。界面配色：青蓝 `#18BFEA` 表示生效计划，橙色 `#FF992F` 突出候选变化，灰色表示对照，完成与异常保留绿色/红色。亮色排程条与按钮搭配深色文字；导航使用白底与青蓝选中态。左侧场景使用等高紧凑行和细分隔线，显示名称、真实状态、工单/执行单元数、版本和最近业务更新时间，窄屏也保留摘要。数量基于已保存数据，草稿另有标记；未打开的场景同样有摘要。待生成方案、已有方案、待重新规划、排队中、求解中、执行中和已结束各有明确含义，不再用“规划中”代替阶段或任务状态。长名称省略并提供完整名称提示，只允许纵向滚动。详细契约和自建底图配置见 [maps-and-import.md](maps-and-import.md)。

数据与规则的工单、执行单元、约束与费用、地点管理共用紧凑工作表，支持单元格编辑、键盘移动、区域选择、Excel TSV 复制粘贴、向下填充、筛选排序及撤销/重做。冻结表头和编号（或参数名）列，长表只渲染可见区域附近的行，横向滚动限制在工作表内部。粘贴先整体校验再应用，错误不留下部分修改；单元格错误明确标红并阻止保存。修改先进入各场景独立草稿，保存后才形成新业务版本，历史任务输入保持冻结。服务中、已完成和已取消工单在工作表中只读。编辑单元格后直接点击页签、工具栏或另一单元格，先提交当前值，待点击完成再重绘，避免丢失目标操作。

约束与费用页包含权重和费用两张工作表，各自筛选，共享场景撤销记录。权重按硬、中、软三列编辑，执行物理一致性保持只读；默认权重与显式零值分别保留。限行费用、模型估算与几何估算排班余量直接在费用表编辑，余量单位为千分比，范围 0～10000。缺省余量消息使用模型 100、几何 200；显式消息中的零值保留为零，不回填默认值。余量只影响排班推时，不改写矩阵原值。

工单服务地点、执行单元出发/返回地点直接在对象行中选择或维护，可以新建地点并同时关联。编辑共享地点时显示引用范围，默认给当前对象另建地点；明确选择共享更新才影响全部引用。地点管理工作表可直接编辑名称、地址、经纬度和备注，编号及关联对象数量只读；修改共享地点会影响其全部引用，完整字段编辑入口保留。新增/移动地点时保留其他地点间原值，仅相关边标记为未知、使用统一估算；名称、地址和备注修改不影响矩阵。批量坐标修改整体校验，撤销同时恢复原坐标和矩阵。删除未被引用的地点同步重排矩阵。通过原生 JSON 调整地点顺序时必须同步调整矩阵。

在途矩阵使用 Canvas 热力总览，行代表起点、列代表终点，可切换车型、时间/距离、起终点筛选和缩放。完整车型矩阵的数值范围决定色标，筛选不重新缩放颜色；保留方向性，对角线、待估算与不可达分别标识。悬停显示数值和关联工单/执行单元，点击或方向键固定选择，地点预览与地图联动。沿用旧场景的数值统一显示“历史导入”。名称、地址、说明由应用层 Scenario.display 保存，Scenario.origin 保存导入来源，matrix_quality 展示输入数值/估算比例；这些展示功能不改变核心评分。

演示数据整理约定：保留精确地理坐标及对应矩阵；脱敏范围为标识、名称、地址和备注等业务文本，使用稳定、易读的编号并保持对象引用一致。这些数据用于私有演示，不作为公开发布的数据集。

任务有独立详情和结果可视化，展示用途、来源任务、状态、停机条件和结果解释。比较跨版本方案时展示输入不同提示，不给出误导性的总分改善结论。执行事件历史分页查询，点击恢复当时业务版本及执行快照，不要求用户手填内部修订号。

## 应用协议扩展

契约以 `proto/vrp/app/v1/app.proto` 为准：继续优化与人工调整是 jobs 的独立操作，Job 记录 kind/source_job_id；StartOperationRequest 可携带 initial_job_id；OperationHistory 提供有界分页摘要；ScenarioDisplay 提供业务展示信息；GetScenarioMetadata 避免轮询完整矩阵。PublishedPlan 路线保存采用时的起止和行驶指标，旧记录缺失时不伪造。上述扩展不改变 engine 评分语义。

## 离线底图包

“路网包管理”保留一级入口，包含路网包与底图包页签。底图包支持按已保存场景准备、预估后补充 15 级、导入服务端 PMTiles、覆盖预览、启停、更新与未引用包清理。首次打开场景地图自动检查，自动准备只提取原生 0–14 级，拖动与放大均不追加下载。详细操作和资源访问边界见 [offline-basemaps.md](offline-basemaps.md)。
