# 开放地图与历史场景

vrp-1 内嵌 MapLibre GL JS 6.16.0 与 PMTiles 4.5.0，版本、包完整性和许可证保存在 `web/vendor/`。`python scripts/vendor_maps.py` 可重建这组固定资源；部署不依赖 Node 或运行时 CDN。

## 导入历史请求

这是离线基准/历史回放工具。运行中的服务只接受 `app.proto` 和 `engine.proto` 原生数据，不读取 vrp-0 格式，不自动访问图商。

```powershell
cargo build --release -p vrp-cli -p vrp-server
python scripts/import_scenarios.py --source <vrp-0的scenarios目录> --server http://127.0.0.1:8080
```

省略 `--server` 只转换。默认输出 `corpus/workbench`；原始文件按 SHA-256 保存，报告每次生成新文件，不覆盖已有语料索引。默认从 `VRP_API_TOKEN` 读取服务令牌，仅发送给指定服务。原生导出文件可通过工作台“导入场景”或 `POST /v1/scenarios` 使用。

转换范围为原始请求；结果、快照、辅助资料仅分类保存。超过 1000 单/200 资源、损坏或缺失必要数据的记录明确报告，不截断实体。相同文件及转换配置得到相同场景 ID；上传已存在的 ID 时跳过，保护人工修改。

默认遵循本次迁移确认的来源规则：明确 HERE 的旧场景按 WGS84；其余按旧高德 GCJ-02 反算到 WGS84，并在 `ScenarioOrigin` 留下假设。`--crs-overrides <JSON文件>` 可按相对文件路径指定 `WGS84` 或 `GCJ-02`；修改覆盖配置会生成新的导入 ID。不要把此默认用于任意未知来源的新数据。

旧格式经纬度顺序沿用现有导入器修正。原有合法矩阵按地点 ID 重排，保持方向性及秒/米数值；缺失项用现有确定性 fallback 固化。矩阵存储未加余量的时间，标记 FALLBACK，20% 默认排班余量仍只在评分时应用。原生不可达值保持不可达；旧 `Long.MAX_VALUE` 按既有契约视为未知，明确 `unreachable: true` 的历史条目在新导出工具中保留不可达。

历史导入数值在引擎中保留原有评分口径。应用层保留 `historical_values_unverified` 字段以兼容既有数据，界面统一显示“历史导入”，仅说明数据来源，不附加核验状态。`MatrixQuality` 不含对角线，区分输入值、估算值及不可达；工作台在途矩阵页可按起终点查看数值。

## 私有演示数据整理

### 已导入场景的前置依赖修正

旧 `dep_tickets` 表示前置工单，`ref_tickets` 通常是对应的下游反向引用，二者合并成同一条有向依赖，不因此推导同资源要求。原文件明确启用独立关联同资源权重的关系仍保留。多个前置必须全部完成，允许不同资源执行；导入依赖时若时序权重缺失或为零，会明确设为 `1 hard` 并报告。

已有工作台场景使用下面的独立迁移工具；普通导入仍跳过已存在的场景 ID：

```powershell
python scripts/migrate_dependencies.py --server http://127.0.0.1:8080 --vrp target/release/vrp.exe
python scripts/migrate_dependencies.py --server http://127.0.0.1:8080 --vrp target/release/vrp.exe --apply
```

默认只生成计划和私有报告，`--apply` 才通过原生场景版本接口保存。工具按来源哈希核对原件，重新转换依赖；只更新仍与旧导入关系匹配的场景，遇到人工修改的关系或无法对应的工单编号会跳过并报告。保留现有坐标、矩阵、工单/资源、展示元数据、历史版本、冻结任务和执行历史，重复运行不会再创建版本。新版本需要重新规划；已有任务的继续优化仍使用原任务冻结输入。使用前应备份服务数据库并在副本验收。原件、转换产物和报告均留在私有 `corpus/`。

### 演示标识整理

```powershell
cargo run -p vrp-server --example prepare_demo -- <未运行服务的演示数据目录>
```

此离线工具将场景标题、工单/资源/地点编号、共享物理资源、技能、资质和网点标识统一整理为稳定易读的演示编号，清理名称、地址、备注和来源文件名中的业务文本。精确坐标、原始矩阵数值、单位、顺序和关联下标保留；既有规划任务同步更新冻结输入中的标识、道路折线引用和幂等指纹，结果中的下标和评分不变。通过逐字段比较、候选资源集合比较和旧方案重新评分验证，任一检查失败则整库事务回滚。数据库记录完成标记，再次执行不会重新编号。

仅用于执行开始前的私有演示准备：拒绝运行中的数据目录、排队/运行任务，以及包含执行历史或继续优化等衍生任务的数据库。已有运营数据不能用此工具直接改写。先在数据副本验收，再对同一来源的停机数据库执行；原始业务语料继续留在项目私有目录，不进入 Git。这些演示数据保留精确位置，不作为公开数据集发布。

## 底图配置

默认离线优先：根据保存场景范围向外缓冲 10 公里，以 HTTP Range 提取 Protomaps v4 原生 0–14 级区域包。首次缺包时后台准备；缺包、准备期间或超出覆盖时允许在线 OSM 标准栅格过渡。禁止预取或批量抓取公共 OSM 栅格瓦片。服务端只托管已登记的离线包；服务令牌仅发送至同源受控地图资源，外部地图服务不会收到。精度、导入、预算和离线验收见 [offline-basemaps.md](offline-basemaps.md)。

`vrp-server --map-config <MapConfig的ProtoJSON文件>` 提供启动配置。前端通过受保护的 `GET /v1/map-config` 读取；修改配置后重启服务。

```json
{
  "styleUrl": "https://maps.example.org/styles/business/style.json",
  "attribution": "© OpenStreetMap contributors",
  "resourceOrigins": ["https://maps.example.org"],
  "maxZoom": 19
}
```

也可使用 `rasterUrl` 模板（`{z}/{x}/{y}`），`styleUrl` 优先；`disabled: true` 使用坐标示意图。样式引用的瓦片、字体、图标和 PMTiles 资源域必须列入 `resourceOrigins`，它用于 CSP 及客户端域校验。URL 可以使用同源相对路径；应用内不提供任意文件托管或图商凭据保存。

PMTiles：在自有 MapLibre 样式中配置 `sources.<name>.url = "pmtiles://https://maps.example.org/region.pmtiles"`，并使用对应数据集的图层定义。部署方提供支持 HTTP Range 和 CORS 的静态服务，以及样式/字体/图标。本轮只提供读取支持，不下载或生成区域地图包。

## 道路折线接口

`GET /v1/jobs/{id}/geometry` 返回 `JobGeometry`；暂无路径时返回该任务 ID、WGS84 和空路段列表。仅终态且有结果的任务可读取/写入。`POST` 同一路径原子替换整组展示折线，可以只提供部分路段。

```json
{
  "jobId": "123",
  "coordinateSystem": "WGS84",
  "provider": "external-osrm",
  "legs": [{
    "agentId": "vehicle-1", "legIndex": 0,
    "fromLocationId": "depot", "toLocationId": "customer-1",
    "points": [{"lng": 121.5, "lat": 31.2}, {"lng": 121.51, "lat": 31.21}]
  }]
}
```

路段序号从 0 开始，包括起点→首单、相邻工单和末单→终点。必须引用该任务冻结输入中的 ID（包括实时重排的辅助地点），与结果的访问顺序一致；车辆、序号、起终点错误或重复路段均拒绝。坐标仅接受 WGS84，每段至少两个有限坐标点，全包最多 5000 段、250000 点，并受请求/存储额度约束。无需道路吸附点精确等于 POI 坐标。

折线单独持久化，纳入容量统计；重复上传同样内容不增加数据占用，删除任务同时删除折线。版本 3 增加折线存储，版本 4 增加任务曲线历史，当前版本 5 增加通用任务、产物和路网包；旧场景元数据字段缺省保持可读。发布回滚需恢复升级前的数据库备份。

界面把有效外部折线画为实线，缺少的路段画为访问顺序虚线。矩阵无法还原路径；道路路径也不代表实际 GPS 轨迹。候选、生效与历史计划分别使用各自任务快照的折线和起点。上传折线不改变矩阵、评分、排程或采用状态。

## 本地路网准备

独立应用提供全 Rust 路网包管理、通用任务与矩阵准备，见 [路网与通用任务](geo-tasks.md)。原始 Geofabrik 包按场景覆盖及新增下载量选择，实际下载整个选中包，本地只构建场景所需范围；不批量下载公共栅格瓦片。

工作台“生成矩阵并规划”依次准备路网、固化完整矩阵、保存新版本、求解及绘制道路路径。直接求解时矩阵未就绪会被拒绝；MODEL 和显式 FALLBACK 均可以构成完整输入。车辆新位置及新增工单缺失的边在准备／重评估阶段明确补齐并固化。继续优化冻结原输入，业务变更重新规划，执行事件触发持续重排，采用仍默认人工确认。

自动化地图测试使用本地合成瓦片及折线，不向公共底图施加测试流量。
