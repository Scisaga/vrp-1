# 路网包、通用任务与矩阵准备

契约以 `proto/` 为准。一级导航为场景、路网包管理、任务中心、服务设置。求解、路网准备、矩阵生成和路径生成共用任务查询、进度、取消、错误和产物入口；求解曲线、分数和执行基准保留在求解详情中。

## 数据和版本

Geofabrik 是默认原始数据来源。全球目录提供实际覆盖多边形、区域父子关系和下载地址。包选择以场景地点包络和绕行缓冲为需求，先扣除已校验缓存，再按新增覆盖与新增字节选择候选，并比较较大包替换与冗余删除。此算法尽量减少新增下载，不声称全局最优。

选中的标准 PBF 需要完整下载；本地构图只处理所需范围。管理页面分别展示场景需求、源包覆盖和构图范围，不能把本地裁剪说成按字节空间下载。默认缓冲 10 公里，可扩至 30 公里重试；跨 180° 经线使用分离包络。

原始包版本按内容哈希固定；派生路由图记录输入包、构建器和速度模型版本。不同场景共享源包，已经开始的矩阵和任务绑定具体版本。更新、启用只改变后续选择，不能改写历史输入或已有矩阵。包清理必须检查场景、任务、图和路径引用。

首次保存或导入触发后台覆盖检查和缺包准备。草稿输入不下载，名称、时间窗或权重变更不要求重新下载。准备回调绑定场景版本和坐标指纹。失败与半成品不计入完整覆盖。源包下载及索引耗时与求解时限分开统计。

场景保存与预取事件写入同一事务；任务创建与事件确认也在同一事务，重启会消费尚未完成的新事件。升级不为已有历史场景回填下载事件。

## 计算口径

真实地点保留，连接到最近候选汽车道路线段上的几何投影点。路径为起点接入直线、道路路径、终点接入直线，两端接入默认 15 km/h。距离远只提示，不要求额外入口确认。交叉道路只有共享 OSM 节点时连接，保留单行与环岛方向。

时间最短路径同时累计其距离。高速、快速路、主路、次路、支路、普通道路、住宅道路、服务道路和生活街道默认分别为 80、60、45、35、30、25、20、15、10 km/h；可解释的数值限速作为上限。参数在生成时固定。

有路网支持的边标记 MODEL；无法计算的部分在准备阶段明确固化为 FALLBACK。已有显式估算配置优先；新场景自动模式可按 30 公里大圆距离区分曼哈顿短距与大圆距离乘 1.3 的长距估算。自动短距模型按最短经度差和起终点平均纬度换算，支持跨经线与高纬地点，不受其他远方地点影响。历史输入及继续优化不切换模型。未知不等于真实不可达，已有不可达标记保留。

MODEL/FALLBACK 的原始时间不提前加排班余量，缓存不改变来源标记。排班余量和评分继续遵守 `constraints-v2.md`。

## 矩阵准入

静态场景的默认生成／重新规划入口统一准备道路矩阵、求解及路径；求解参数在提交前选择。仅使用已有矩阵的求解保留在更多菜单，明确说明不生成道路路径。历史方案缺少折线时，地图显示生成新道路方案的入口，原冻结矩阵和方案保持可回放。

所有新求解输入先完成准备并固化。求解叶任务检查车型矩阵存在、尺寸和下标一致、对角线为零、时间/距离合法、保留值成对且无 UNKNOWN。完整外部输入可以直接通过；路网失败但已显式生成完整几何估算矩阵也可以通过。

直接请求求解而矩阵未就绪应明确拒绝。一键规划先创建准备流程，只有矩阵成功后才创建求解子任务。继续优化使用原冻结问题；实时重排、执行启动和采用重评估只补齐新增位置或辅助地点相关的未知边，保留已有矩阵，并复核执行基准。

道路折线绑定同一任务输入、路网图和吸附参数。道路部分为实线，接入部分为虚线；没有道路支持的估算边继续显示访问顺序示意。路径失败可以单独重试，不使已完成求解结果失效。

## 调度与恢复

任务父子关系和依赖关系分开保存。矩阵到求解是必需成功依赖；地图获取可有界等待后使用显式估算。默认下载并发 2、路网计算并发 1、场景自动新增下载预算 500 MiB、首次路网等待 180 秒。

全部计算共用 CPU 与内存预算；真实额度只取得一次，子进程及 I/O 线程回收后释放。通用启动、心跳和取消宽限独立于求解搜索时限。PBF 和索引使用受控产物目录，IPC 仅传元数据和产物引用。

重试和恢复依据幂等键、已提交的不可变产物及版本记录接续。矩阵失败不启动求解；求解失败保留矩阵；几何失败保留方案。取消某个场景流程不能取消其他场景仍引用的共享准备任务。

运行中任务不能直接重试。静态求解沿用冻结输入和用途；执行任务使用当前执行事实重新投影并校验基准；人工调整重新评估原方案。连续重启会沿重试祖先查找已经提交的求解，避免重复创建。

历史任务保留原 ID、请求、结果、分数、曲线、折线及执行引用。迁移不把历史输入替换为新路网矩阵。不完整旧排队输入不能绕过准入校验。

## 验收

自动测试使用本地合成目录、PBF/道路图与 HTTP 服务，不向公共底图或 Geofabrik 施加测试流量。真实场景验收在数据库副本进行，原件、导出和报告保留在被 Git 忽略的 `corpus/`。

```powershell
cargo test --workspace
cargo clippy --workspace --all-targets -- -D warnings
cargo build -p vrp-server
python scripts/smoke_geo_workbench.py
```

浏览器脚本需要开发机安装 Playwright 和 Chromium；它启动独立服务、本地目录服务器和合成 PBF，检查自动准备、并发场景共享下载、矩阵门禁、一键规划、道路折线、任务产物及移动布局。Python 仅用于离线验收，服务部署不依赖 Python。
